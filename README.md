# The Pilates Programme, Altrincham

Website rebuild: Astro 5 (static, with a few server routes) + Sanity CMS + Vercel. Built to the spec in `SPEC.md` terms: every value in the design system is a token, every price, date and claim renders from CMS content, and no page may claim "Level 3", "Ofqual", "NVQ" or "regulated" for Mat, Reformer or Barre.

## Quick start

```bash
npm install
cp .env.example .env        # fill in what you have; everything works without Sanity using the seed content
npm run dev                 # http://localhost:4321
npm run build               # prebuild writes vercel.json + public/llms.txt, postbuild runs the banned-terms check
npm test                    # unit tests (Arketa links, redirects, dates, banned-terms checker)
npm run test:e2e            # Playwright (BASE_URL=... to point at a preview deployment)
npm run test:schema         # JSON-LD presence and validity (BASE_URL=... for a preview)
```

## How content works

`src/lib/content.ts` is the only place pages read content from. When `PUBLIC_SANITY_PROJECT_ID` is set it queries Sanity (GROQ projections match the seed shapes). When it is not set it reads `src/content/seed/*.json`, which is the same data in Sanity document shape. `npm run seed:ndjson` converts the seed into `seed.ndjson` for `sanity dataset import` (see `studio/README.md`).

Anything marked `[CLIENT TO CONFIRM]` in the spec is an empty CMS field that the template hides until it is filled: proof-bar stats, studio hire rate, Advanced Reformer price, typical class rate for payback maths, travel times, founder bios and credentials, accreditation wording per body, the employer note, Samhar's story, Elevating Others eligibility and window, the free guide PDF, the Adobe Fonts kit.

## Motion

Follows spec 4.7 and section 5.6 of the UI/UX playbook (Google Drive, "02 UI UX Playbook"): every animation is functional, transitions are spatial rather than plain dissolves, and interactive elements have eased micro-interactions. All durations, curves and offsets are tokens in `src/styles/tokens.css`; utilities live in `src/styles/global.css`.

| Pattern | Where | How |
|---|---|---|
| Entry on scroll, once | every section | `.reveal`: fade + 16px rise, `--dur-slow` / `--ease-out` |
| Staggered entry | card grids, timelines, value lists | `[data-stagger]` children delayed by `--stagger` in reading order |
| Home hero video | home page | The client's header film (Website_Header.mp4), audio stripped, poster is its first frame. Poster is the LCP; video attaches after load, WebM VP9 with MP4 fallback, 720p under 1024px, pauses off screen, pause button for WCAG 2.2.2, never plays under reduced motion or Save-Data. Files in `public/video/header-*`; supply replacements at 1920×1080, subject centred. |
| Text over media | Hero, PathTile, Breadcrumbs | Photos and video render under an ink scrim (`--scrim` tokens) sized so text passes WCAG AA even over a pure white frame. Accent text on media uses `--text-on-media-accent`. Any new video needs no per-file tuning. |
| SEO basics | `scripts/check-seo.mjs` (postbuild) | Fails the build on a missing title, description, canonical, og:image or favicon, a page without exactly one H1, an image without alt, or duplicate titles or descriptions. Warns on titles over 65 or descriptions outside 70 to 160 characters. Icons: `favicon.svg/.ico`, `apple-touch-icon.png`, `site.webmanifest`. |
| Spatial open and close | mega-menu, mobile sheet, quiz steps, sticky bar, cookie banner, form status | `.motion-pop` / `.motion-sheet` / `.motion-step` with `@starting-style` and `allow-discrete` on `hidden` |
| Eased disclosure | FAQ accordion, course date details | `.disclosure::details-content` animates height and opacity |
| Micro-interactions | buttons, inputs, cards, arrow links | press offset, border and colour eases, image lift, arrow slide |
| Data read in order | hours bar | segments grow from the left with a stagger when the section enters |

The playbook's 3D transitions and animated 3D clay icons were deliberately not used: they conflict with the spec's quiet, editorial direction. Everything collapses to instant under `prefers-reduced-motion: reduce`.

## World map and Google reviews

- **Where our students are teaching** (home page): locations live in site settings (`teachingMap`) and are editable in Sanity, including label offsets. `scripts/build-world-map.mjs` renders the dot-matrix land layer to `public/images/world-dots.svg` at build; markers, labels and arcs from Altrincham are drawn inline with the same projection (`src/lib/worldmap.mjs`). Phones zoom to the pins and use the list below the map for names.
- **Google reviews**: `scripts/fetch-google-reviews.mjs` runs at build and calls the official Google Places API (New). Set `GOOGLE_PLACES_API_KEY` and `GOOGLE_PLACE_ID` in Vercel (find the ID with `--find`). The rating badge, the proof bar's Google rating and relevant 4 and 5 star reviews then appear in the testimonial section with Google attribution. The API returns the rating, the total count and up to five reviews Google picks. Without a key nothing Google-related shows. Reviews are never scraped or written by hand into `googleReviews.json`.

## Analytics

GTM is loaded only when `PUBLIC_GTM_ID` is set. Consent Mode v2 defaults everything to denied; the banner stores the choice in `localStorage` and pushes `consent_update`. Data-layer events from Section 9.3 are pushed by `Base.astro` (book_click, view_dates, scroll_depth, job_apply_click, page_not_found), the form enhancer (lead_submit, job_submit, graduate_submit, contact_submit) and the quiz (quiz_start, quiz_complete). GA4 and Meta Pixel tags, plus the Conversions API, are configured inside GTM against those events, gated on consent.

## Server routes on Vercel

Jobs listing and detail pages are server-rendered with `s-maxage=60` so an approved role is live within a minute without a rebuild. Expired roles return 410 with a notice. All other pages are static. `VERCEL_DEPLOY_HOOK_URL` lets the Sanity webhook trigger a rebuild for everything else.

## Environment variables

See `.env.example`. Nothing is required to build locally. For production: Sanity project ID and write token, GTM ID, Turnstile keys, Resend key, `CRON_SECRET`, `SANITY_REVALIDATE_SECRET`, `VERCEL_DEPLOY_HOOK_URL`, and the lead provider (`LEAD_PROVIDER=kit` with `KIT_API_KEY`).
